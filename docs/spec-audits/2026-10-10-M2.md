## Blockers

### F-1 · blocker · `agent_runs` has no DDL
- **Section:** Domain model and storage › "The tables built in M1 and M2"
- **Evidence:** line 299 "M2 `plans`, `tasks`, `task_deps`, `agent_runs`"; the DDL block (lines 240-287) has `plans`, `tasks`, `task_deps` and no `agent_runs`. The Projections table (line 231) gives column names only, and has no `duration_s` or `error` although `AgentRunFinished` carries both (lines 367-372). `tests/unit/test_spec_conformance.py` compares each `CREATE TABLE` block with the projector, so M2 has nothing to compare against.
- **Proposed fix:** add `CREATE TABLE agent_runs (id TEXT PRIMARY KEY, task_id TEXT, role TEXT NOT NULL, runtime TEXT NOT NULL, model TEXT, started_at TEXT NOT NULL, ended_at TEXT, exit TEXT, tokens_in INTEGER, tokens_out INTEGER, cost_usd REAL, context_hash TEXT NOT NULL)`; the columns filled by `AgentRunFinished` are nullable. Say whether `duration_s` and `error` are projected (proposal: add both as nullable columns, since `stats` needs latency, see F-12).

### F-2 · blocker · `AgentRunFinished` has untyped fields, and a failed or rejected planner call has no defined outcome
- **Section:** Domain model and storage › Event payloads; Tech stack and repo layout; Task contract › Plan checks; Metrics
- **Evidence:** line 371 "tokens_in, tokens_out, cost_usd, duration_s" has no types; line 326 "Every payload field is required, nullable ones included" does not say which of these are nullable, and a timed-out call reports no tokens. Line 70 defines the retry only for a reply that "fails Pydantic validation"; decisions row 2026-10-08 (G18) says "a process failure or timeout raises `LLMError`"; decisions row 2026-10-09 (SC-6) says "Whether a timeout or a failed process is retried is not decided here and stays under Later". Line 369 `exit: "ok" | "error" | "timeout"` does not say which value a run gets when the reply came back but was rejected by Pydantic or the plan checks (line 620 "a rejected call keeps its cost"). ADR-007 makes payloads stable contracts, so the shape must be fixed before the model is written.
- **Proposed fix:** type them `tokens_in: int | null`, `tokens_out: int | null`, `cost_usd: float | null`, `duration_s: float`; null when the runtime reported none. A timeout or a failed process is not retried: the run is recorded with `exit: timeout` or `error` and `error` set, no `PlanCreated` is recorded, and `plan` exits 1. A reply that was returned and then rejected has `exit: ok` and `error` set to the rejection list as text, so the evidence is in the log.

### F-4 · gap · the events `plan` and `approve plan` record, their order and `causation_id`
- **Section:** Domain model and storage › Streams and actors, Event payloads; Metrics
- **Evidence:** line 322 fixes `causation_id` for the spec events and gives one example for `approve plan`; nothing says the `causation_id` of `AgentRunStarted`, `AgentRunFinished` or `PlanCreated`. Line 620 "`AgentRunStarted`, then `AgentRunFinished`. A retried call is a second run" does not say whether `AgentRunStarted` is recorded before the call is made (so a killed process leaves a started run) or after it returns. The order of the `TaskStateChanged` events of `approve plan` and the order of `PlanCreated.tasks` ("as the orchestrator stored them", line 349) are not stated; M1 needed the same detail (SC-9, SC-16).
- **Proposed fix:** `plan` records `AgentRunStarted` before the call and `AgentRunFinished` after it; each `AgentRunFinished` points at its `AgentRunStarted`; a retry's `AgentRunStarted` points at the first run's `AgentRunFinished`; `PlanCreated` points at the `AgentRunFinished` of the accepted run. `PlanCreated.tasks` keeps the reply's order. `approve plan` records `PlanApproved`, then one `TaskStateChanged` per task with no dependencies in the order of `PlanCreated.tasks`, each pointing at `PlanApproved`.

### F-5 · gap · output, messages and exit codes of `plan` and `approve plan`
- **Section:** CLI commands › Output; Task contract › Planning
- **Evidence:** "Output" (lines 657-663) defines lines for `validate`, `approve spec` and `events` only; for the M2 commands it has one sentence, "`approve plan` fails if there is no draft plan" (line 660). Every refusal writes one fixed message to standard error and exits 1: `no approved spec version`, `policy is invalid; run openfactory validate`, `plan_NN is already approved for sv_NN; use replan`, `planner call failed: <error>`. The warning `spec files differ from approved sv_NN` goes to standard error and also covers files that cannot be loaded. `approve plan` prints `approved plan_NN` and one line per task made ready, or writes `no draft plan` to standard error and exits 1.

### Q2: Is F-2 real (untyped `AgentRunFinished` fields, no outcome for a failed or rejected planner call), and is the fix right?
- Proposed: `tokens_in/out: int | null`, `cost_usd: float | null`, `duration_s: float`; a timeout or failed process is not retried and `plan` exits 1; a returned-then-rejected reply has `exit: ok` with `error` holding the rejection list.
- Challenge: The evidence checks out (lines 70, 326, 369-372, 620; decisions rows 2026-10-08 G18 and 2026-10-09 SC-6). Two things are unstated.
  - A non-null `duration_s` on a failure has no source: `LLMError` has no fields in the G18 row. Either `LLMError` carries the duration or the use case times the call.
  - `error` can only hold the rejection list if `AgentRunFinished` is recorded after the Pydantic and plan checks. The fix should say so.
  - "Not retried" and `exit: ok` for a rejected reply are new decisions; no document settles them.
- Strongest alternative: `exit: error` for a rejected reply, so one field answers "usable result?". Against it: for an implementer run the same field means the process outcome (`RunResult.exit_status`, line 518), with gate failures recorded elsewhere.
- Conflicts: none. ADR-007's "every field is required" is met by null.
- Recommendation: the proposed fix plus the two sentences above — no retry means fewer model calls (priority 5), and `exit` keeps one meaning for every role.
- Class: blocker is right.
- Verdict: AGREE
